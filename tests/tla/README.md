# TLA+ models

TLA+ specifications for fx, checked with TLC, together with the scripts and Bun drivers that check them. CI runs the SDK, MCP, transcript window, subagent, session-write, and live sessions models on `main` and on pull requests that change the code they cover, as `scripts/detect-ci-need.sh` decides; the `fx mcp call` model on `main` and on pull requests labeled `ci:tla-mcp-call`; and the recovery, gateway_open, agent_runtime, and compaction_progress models, each with its driver, on every pull request. Run the others when you change the behavior they describe.

## Requirements

Java 11 or later and `tla2tools.jar`:

```sh
brew install openjdk
mkdir -p ~/.local/share/tla
curl -fL -o ~/.local/share/tla/tla2tools.jar \
  https://github.com/tlaplus/tlaplus/releases/latest/download/tla2tools.jar
```

Set `TLA2TOOLS_JAR` to use a jar in another location. The scripts look for Java in `JAVA_HOME`, then in Homebrew's OpenJDK, then on `PATH`. The `mcp/`, `durable/`, and `session_manager/` runners also need Python 3.

The drivers need Bun. Most of them also run the binary that `zig build` puts in `zig-out/bin/fx`, and the terminal ones need tmux. They take these settings from the environment:

| Variable | Default | Effect |
|---|---|---|
| `FX_BIN` | `zig-out/bin/fx` | The binary under test |
| `FX_WORKTREE` | this checkout | The checkout whose binary and `tests/e2e/` helpers a driver uses |
| `FX_TLA_OUT` | a folder under the system temp folder | Where traces, TLC logs, and reports go |
| `FX_SOUND` | `0` in every driver | Keep it at `0`; sound playback can overload a machine during a run |

The SDK drivers also need the native addon and the durable World packages:

```sh
zig build libfx-napi -Dnapi-surface=core
npm ci --prefix sdk/durable
```

## MCP in CI

CI runs MCP in four parallel jobs, on `main` and on pull requests that change MCP code, these models, their drivers, or the files the drivers load. `TLA+ MCP engine models and driver` runs each engine model's smoke config (`mcp/run.py check`) and the engine driver (`drivers/mcp/driver.ts`). `TLA+ MCP host SignIn model` and `TLA+ MCP host other models` run `models.test.ts`, which checks the host models and runs every host model's smoke and stress configs, planted bugs, findings, and repair witnesses: the catalog `mcp_host/check.sh` runs by hand, so CI doesn't run that script too. SignIn is half of the TLC time, so it has its own job (`FX_MCP_HOST_MODELS=SignIn`); the other job checks every other model (`FX_MCP_HOST_MODELS=-SignIn`) and runs the file's bridge controls. `TLA+ MCP host drivers` runs every other test file in `drivers/mcp_host/`. The engine models' planted bugs (`mcp/check.sh`) run only by hand: they measure the checks, not the code.

`.github/workflows/tla-mcp-call.yml` runs `mcp_call/check.sh`, planted bugs included, on every push to `main` and on pull requests labeled `ci:tla-mcp-call`.

## Custom model connections in CI

## ACP notices

`acp/AcpNotices.tla` models what `fx acp` sends for each kind of text the agent runtime emits about a turn (`src/acp/prompt.zig`), to a client that advertises ACP v1 Session Notices and to one that does not. The text that says why a turn failed, the HTTP failure that ends a request, the text fx saves as the reply (such as "Done."), the reply itself, and diff previews stay agent messages for every client. The empty-reply nudge, the length resend, restarts, other operational text, and system notices reach a notices client as one notice per message, and a plain client as the agent messages it always got. A turn ends for one of five causes: an HTTP failure, a provider error event, a response-language failure, the step limit, and a second empty reply. The text of each is flagged as ending the turn, and `NoTurnEndingNotice` says no flagged text is a notice for any client, because a client may ignore a notice and the prompt then answers with only an error or a stop reason. The provider error and the language failure reach ACP through the turn-failure notice hook (`push_turn_failure_notice` in `src/core/agent/runtime/deps.zig`), which only ACP sets; every other host shows them as system notices. `MCAcpNoticesBefore` is fx before that rule, `MCAcpNoticesHeadProviderError` and `MCAcpNoticesHeadLanguage` are fx before the hook, where one of those two exits still sends a system notice, and five planted bugs must each be caught by their named rule. `bun tests/tla/drivers/acp/notices/driver.ts` runs the built `zig-out/bin/fx acp` for both clients against a local gateway, including turns that end on a provider error event and on a response-language failure, has TLC check each turn through `AcpNoticesTrace.tla`, checks that a notices client's agent messages match what `session/load` replays, and checks that a client gets no chunk after the text that ends a turn; `--stress N` adds one turn with N stalls.
