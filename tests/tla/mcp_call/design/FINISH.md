## B. The bridge shell (`src/core/mcp_host/`)

The bridge is built. An item stays open until its own done criterion has evidence; each says what is still missing.

- [ ] **B1** Listener: a Unix socket in a private (0700) per-session directory, bound on the session's first shell command, never before the first frame. A stale socket file is removed at start, and a bind on an existing live socket fails instead of sharing it. Done when Zig tests cover the directory mode, stale removal, and an exclusive bind, and `Startup Latency` passes in CI. Status: built; the listener starts for the first registered shell call, in a new random 0700 directory, so no stale socket can exist, and a test checks the socket is removed after the last call. Missing: a test of the directory's mode, and CI.
- [ ] **B2** Framing: one JSON request line per connection, at most a fixed byte cap, parsed into `Event.request`. Garbage and oversized lines are refused before the core and logged. Replies are length-framed. Done when Zig tests cover each refusal and a new fuzz target for the parser is listed in `tests/fuzz/targets.json`. Status: built in `mcp_call_wire.zig`, with tests for garbage lines and a reply header round trip. Missing: the fuzz target.
- [ ] **B3** Permission adapter: `authorize` runs `tool_admission.requestPermissionOutcome` for the tool and its arguments, as the owner, with the prompt shown while the command runs. It checks that the tool exists and is permitted even though the model never advertised it. `withdraw` takes the prompt back and answers `deny`. Done when a TUI E2E test with a fake gateway and the fake MCP server covers allow, deny, a withdrawn prompt, and auto-mode review. Status: built; by design a prompt stays when its client leaves, and nothing runs after it is answered, so there is no `withdraw` prompt to take back. Covered: in the TUI, the call's own prompt while the command waits, then an allow (E2E); deny by a configured rule (E2E); and a client leaving during its prompt (Zig). Missing: an auto-review test.
- [ ] **B4** Call adapter: `call` runs `Catalog.callTool` with the owner's `Access`, the runtime generation, a cancel flag, and a full-result path, without the 64 KiB cut, bounded by the configured limit. `cancel` sets the flag. Done when an E2E test pulls a result larger than 64 KiB in full into a file, and the session's `session.json` does not contain it. Status: the E2E test saves a 1.5 MiB result whole, and the model saw under 4 KiB. Missing: the `session.json` check on a saved session.
- [x] **B5** Environment: the shell tool adds the bridge variable, naming the socket and the owner's token, for the session and each subagent. Done when an E2E test runs `fx mcp call` from a shell command and from a subagent's shell command. Status: done. `FX_MCP_CALL_SOCKET` and `FX_MCP_CALL_TOKEN`, one token per shell call. The E2E tests in `tests/e2e/mcp-stdio.test.ts` cover a shell command and a subagent's shell command, both allowed and denied.
- [x] **B6** Replaced: an owner is a running shell call, not a session or subagent, so `owner_added` and `owner_removed` follow `register` and `unregister`, and `max_owners` bounds concurrent shell calls instead of subagents. Done when Zig tests register and unregister shell calls: the four bridge tests.
- [ ] **B7** Drop logging: each `log` effect becomes `debug_trace.logf("mcp-call", ...)` with the id and the drop, and the shell logs effects it could not run. Done when a Zig test checks the trace lines. Status: built in `applyLocked`; a live run's trace shows the bridge's lines. Missing: the Zig test.
- [x] **B8** UI: one row per bridge call, the row a direct call of the same MCP tool gets (`Running MCP`, then `Ran MCP`), in its shell call's group. Changed from an activity line with the server and size through `observer.beginMcp`: the TUI does not read that observer, and the user chose the direct call's row. Done when a TUI E2E test asserts the rows. Status: done. The TUI tests in `tests/e2e/mcp-stdio.test.ts` see a three-page loop show `● 4 tool calls · 3 MCP calls · 1 command` with three `Ran MCP` rows, and a cancelled call show `Running MCP` and then `Cancelled`.
