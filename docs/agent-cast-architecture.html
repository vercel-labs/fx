01

The system map

A bounded logical plan describes the requested calls. The host admits each resolved action. The optimizer changes only eligible physical execution; the actor runtime owns resources and recovery.

Proposed / execution planning

Effect-aware execution optimizer

Transforms eligible admitted logical calls into guarded physical work while preserving the declared observable contract.

  • Each original call retains its authority, budget, result, and receipt.
  • Trusted effects constrain reuse, batching, scheduling, and executor selection.
  • Runtime guards recheck resource identity and generations before start.

Ownership

Each mutable resource has one owner. The owner serializes state changes and can delegate concurrent I/O.

Isolation

Arbitrary tool code runs in a worker or sandbox. A logical actor in the broker is not a memory isolation boundary.

Portability

Language adapters use the operation contract. Backends report their actual containment and lifecycle capabilities.

02

An effect-aware
execution optimizer

Compile declared tool execution plans into guarded physical work. Optimize the operation graph; existing language runtimes continue to execute Python, JavaScript, and shell code.

Compiler / proposed

Logical plan → physical plan

The intermediate representation (Tool IR) preserves original call IDs, arguments, dependencies, budgets, and result contracts. Trusted registrations supply effect summaries and executor equivalence rules.

The optimizer can share certified immutable computation, group transport, and schedule independent work. It must retain required errors, audit events, effects, and publication order.

Actor runtime / proposed

Resources with owners

The runtime retains workers, clients, and workspaces. It owns admission queues, lifetimes, cancellation, output credits, generation checks, and effect receipts.

Pooling reuses setup. Each required application request still executes. A repeated HTTP GET or SQL query does not become a pure expression because its client is persistent.

The compiler must be able to decline optimization. A live read is not an immutable observation; a shell command is not a native read by resemblance; an unused result does not erase a requested action. Unknown effects remain barriers.

Compile fixed plans and currently ready graph segments. Dynamic arguments require preparation and admission after their inputs arrive. Arbitrary Python or JavaScript orchestration runs in its admitted runtime; the pre-admission planner does not execute or statically understand arbitrary code. MCP tool annotations also require a trusted source; annotations alone do not establish purity.

call, cast, monitor

Use tracked calls for effects, notifications for events, and monitors for lifetime changes. An unacknowledged cast is not a durable mutation API.

Same operation, same identity

Bind identity to the principal, tool implementation, exact arguments, and task/workspace lease. Reconnect queries that operation. Reject reused IDs with different bindings; retries do not automatically authorize repeating an effect.

Bounded data movement

Length-framed JSON-RPC control travels over a persistent local Unix socket. Negotiate a maximum frame size and reject oversized frames before allocating. Separate output transport uses byte credits, sequence numbers, quotas, and artifact handles.

Deadline and cancellation

Queue time consumes the execution budget. Reconnect cannot extend the stored deadline. Cancellation acknowledgement means observed; a terminal receipt describes effects.

Durability by operation class

Persist recovery-relevant intent before dispatch. Cheap reads can use ephemeral receipts; syncing every read could dominate its execution time.

Uncertain external effects

A service may commit before a worker loses its reply. Reconcile through an idempotency key or service evidence. Infrastructure restart alone cannot prove exactly-once effects.

Explore a failure

What should restart?

A control actor can reconstruct state. A failed tool operation can require reconciliation even after its worker has been replaced.

Select a failure boundary

Logical actors share a native process. Their ownership rules do not create BEAM-style memory isolation; a native fault can still terminate the broker.

Cooperative stop

Stop admission, request cancellation, and allow bounded cleanup.

Forced stop

Terminate the owning process or containment domain after grace expires.

Fencing

Invalidate old actor epochs and leases before replacement state is published.

Restart limits

Apply a bounded restart budget and backoff. Repeated failure quarantines the resource.

Actors are state machines, not one OS thread each. Keep trusted bookkeeping bounded; delegate blocking I/O. Unknown native plugins belong outside the broker process.

A Zig implementation would not inherit BEAM's preemption, garbage collection, or process isolation. Choosing Zig supports integration with fx; this research does not establish BEAM as a performance bottleneck. Erlang process efficiency.

06

Batch the work.
Preserve each action.

The Tool IR keeps data and control dependencies. The optimizer groups eligible ready work; unresolved actions and effect barriers remain explicit.

Effect-aware scheduling

  • Immutable reads can run concurrently.
  • Workspace mutations hold an exclusive lease.
  • Opaque execution invalidates mutable derivations before it starts and retains its exclusive lease until contained descendants are quiescent.
  • Transactions retain their service-session lease.
  • The trusted registration derives access; model-supplied purity claims do not establish it.

Two optimization tracks

Transport batching preserves individual tool requests and results. Programmatic tool calling lets the model express loops, transformations, and dependencies in code.

Programmatic calling can reduce inference round trips and intermediate context. It changes the model's affordances, so evaluate quality separately from execution latency. Established code-execution pattern.

Fresh

Per-call state

Preserve the harness's fresh interpreter promise. Preloading cannot silently retain a previous call's globals, descriptors, or threads.

Session

Task-owned state

Retain imports and state within one task. Worker loss changes the epoch and reports state loss to the caller.

Template

Qualified preparation

Create fresh workers from a tested, uncredentialed template. Fork safety and cloned state require qualification.

Whole-workspace exclusion is the initial policy. Reject conflicting batch nodes without explicit dependencies so lock acquisition cannot choose a different write order. Command exit alone does not establish quiescence; cache eligibility returns only against a newly established immutable revision. Fine-grained path locking must account for aliases, symlinks, hard links, mounts, and directory mutations. External editors bypass broker locks, so live host workspaces remain ineligible for immutable-result caching.

Reuse an existing containment backend

Start with one Linux backend. OCI images and OpenSandbox provide packaging and lifecycle interfaces; Docker is a practical comparison baseline.

Qualify portable VM options for macOS clients. A Linux guest cannot reproduce native macOS builds or host facilities with identical semantics.

Native same-UID workers are a trusted execution mode. Socket permissions and descriptor hygiene alone do not establish containment from hostile code.

OpenSandbox API · Microsandbox candidate

The reset contract

  1. Fence the taskReject new starts and invalidate old leases and epochs.
  2. Resolve outstanding workFinish, cancel, or retain an explicit unknown outcome.
  3. Stop the containment domainRequest graceful shutdown, then force termination after grace.
  4. Verify process drainConfirm descendants cannot keep writing. Process-group termination has weaker guarantees than qualified containment.
  5. Revoke resourcesClose routes, credentials, subscriptions, and task-scoped handles.
  6. Discard owned task stateDispose of runtime-owned overlays and temporary storage. User mounts and external databases have separate lifetimes.
  7. Initialize the replacementUse pinned images, fixtures, versions, environment, and fresh worker identities.
  8. Probe the boundaryCheck prior files, jobs, state, handles, and credentials are absent. Quarantine failed resets.
Memory snapshots can duplicate randomness, identifiers, and credentials. Network connections may not survive restoration. Prepare templates before credential injection and retain external client pools outside the snapshotted guest. Firecracker snapshot constraints.

Declare the evaluation mode

Reconstruct declared task state and run actual tools. Warm images and permitted pooled clients may remain, but previous trial mutations and cached stateful observations cannot carry over. Measure performance and independently grade terminal effects.

run manifest = task + harness commit + model/provider configuration + image + workspace snapshot + environment + tool/schema versions + clock/randomness policy + budgets + network fixtures + warm-state policy

ThinkingBox provides a relevant evaluation pattern: fresh backend state per attempt, repeated trials, terminal-state grading, and checks for extra effects. A deterministic environment does not make model outputs deterministic.
